# Cursor 规则目录管理规范（study-reward-app）

本目录下的规则供 Cursor Agent 与协作者共同维护。目标：**按类目分文件、短而可执行、单一事实来源、避免重复与冲突**。

## 目录结构

```
.cursor/rules/
├── _meta/           # 本规范与说明（非 .mdc，不参与 Cursor 规则注入）
├── core/            # 全项目架构与分层（与具体后端实现解耦）
├── integration/     # 与外部系统、多服务联动的约定
├── api/             # 仅针对 src/api 的实现细节
├── frontend/        # 仅针对视图层的约定
└── deploy/          # 构建、代理、CI/CD、运维命令
```

新增类目时：在对应文件夹下新增 `.mdc`；若无合适类目，先扩展 `_meta/README.md` 的类目表，再建子文件夹。

## 文件与命名

- 扩展名：`.mdc`（Cursor Rules）。
- 命名：`kebab-case.mdc`，文件名概括**唯一主题**（如 `http-client.mdc`，不要一个文件塞多域）。
- 一个文件只服务一条「规则边界」：架构不分写 HttpClient 字段细节；HttpClient 不分写 SSO 业务 URL 清单。

## Frontmatter 约定

| 字段 | 说明 |
|------|------|
| `description` | 一句话说明适用范围，便于规则列表检索。 |
| `alwaysApply` | 仅当规则属于「改任意代码都可能踩坑」的全局约束时为 `true`；默认优先 `false`。 |
| `globs` | 与路径强相关的规则必须配置，避免无关上下文占用 token。 |

**冲突处理：** 同一话题只在一处写完整说明，其它文件用一句话引用路径（例如：「环境变量与 SSO 见 `integration/microservices.mdc`」），禁止复制粘贴大段相同内容。

## 撰写原则

1. **单一事实来源（SSoT）**：环境变量、ApiResponse 形态、兑换接口路径等只在一类目中完整描述。
2. **短**：能列表不长篇；示例代码只保留最小可说明片段。
3. **可执行**：用 ✅/❌ 或必须/禁止 写清行为，避免泛泛描述。
4. **解耦**：`core` 不写具体微服务名以外的部署细节；`deploy` 不写组件样式。

## 与项目其它文档的关系

产品说明、架构长文若存在，应链接到仓库文档；本目录只保留 **对写代码有直接约束** 的条目。
