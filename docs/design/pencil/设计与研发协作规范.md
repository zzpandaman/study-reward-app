# 设计与研发协作规范（最小版）

## 目标

- 保持 `docs/design/pencil/design-sources` 与前端代码结构一致。
- 以“最小可验证改动”推进，不做一次性大重构。

## 协作流程

1. 代码改动先落地到 `src/pages` / `src/layouts` / `src/components`。
2. 同步更新对应 `.pen` 页面骨架与 `code-map.md` 映射。
3. 涉及视觉基础能力（色值、字号、圆角、间距）时，同步更新 `study-reward.tokens.pen`。

## 约束

- 新页面优先复用既有目录风格，不新增平行目录体系。
- 设计稿命名与 Route/Page 对齐，便于脚本和人工检索。
- 首版初始化阶段仅维护“可迭代骨架”，不追求高保真视觉稿。

## 页面骨架验收口径

- 顶层 `page_*` frame 可正常读取（非空文件）。
- 页面存在至少一个业务主区域（如 `content/*`、`form/*`、`list/*`、`detail/*`）。
- 各页面语义分区命名清晰，便于后续批量检索与局部替换。
