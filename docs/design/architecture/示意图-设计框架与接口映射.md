# Figma 设计原稿：设计框架、交互与接口映射

本文档基于**当前仓库内全部 Figma 导出原稿**（见 §0.2），还原**信息架构、页面/区块/叠加层/表单**的交互，并将可落地的步骤映射到 **star-sso**、**star-reward** OpenAPI（路径以 `/api/sso/*`、`/api/reward/*` 为准）。  
**无对应接口**的能力标注为 **〔缺口〕**，实现前需与后端约定或通过前端本地态兜底。

**说明**：设计稿中出现品牌名「CloudLearn」等，产品对客名称为 **「积分大师」**；交互与接口逻辑一致。

### 2.2 登录 Tab — 控件与接口

| 元素 | 交互 | 接口 / 逻辑 |
|------|------|-------------|
| 电子邮箱 | 输入 | 作为 `username` 或与 SSO 约定字段映射 |
| 密码 | 输入；小眼睛 | 切换 type 文本/密码，**无接口** |
| 忘记密码？ | 点击 | **〔缺口〕** SSO OpenAPI 未列找回密码；可占位页 |
| 保持登录状态 (30 天) | Checkbox | **〔缺口〕** 依赖 SSO 颁发 Token 的 TTL/Refresh 策略；前端可记 localStorage 偏好 |
| 主按钮「登录」 | 提交 | `POST /api/sso/login`；成功 → `setToken` → 进壳层 |
| Tab「注册」 | 切换 | 仅 UI 状态 |

### 2.3 注册 Tab — 控件与接口

| 元素 | 交互 | 接口 / 逻辑 |
|------|------|-------------|
| 用户名 | 输入 | `register` body 的 `username` / `nickname` 与后端约定 |
| 电子邮箱 | 输入 | `email` |
| 密码 / 确认密码 | 输入 | 前端校验一致后提交；**〔缺口〕** 若 SSO 无 confirm 字段则仅发单次 password |
| 主按钮「创建账户」 | 提交 | `POST /api/sso/register`；成功若返 token 则同登录入壳 |
| Tab「登录」 | 切换 | 仅 UI |

### 2.4 进入壳层后的建议请求顺序

1. `GET /api/sso/user/info` — 侧栏用户卡、设置页账户区只读展示。
2. `POST /api/reward/user/points` — 全局积分展示（若顶栏或记录页需要）。
3. 控制台额外数据见 **§4**。

## 4. 控制台（侧栏 1）—「积分获取控制台」

### 4.1 路由与跳转

- **入口**：侧栏「控制台」；部分子页「返回控制台」回到本页。
- **出口**：「查看全部」→ **§5 积分模版列表**；模版卡片 **播放** → 右侧 **专注小窗** 进入进行中态；小窗 **展开** → 专注全宽/全屏布局（仍为本路由或 query `?focus=expanded`）。

### 4.2 主区结构层级

```
Page-Console
├── Header
│   ├── 标题「积分获取控制台」+ 副标题「持续专注，实时结算奖励」
│   └── 右上徽章区
│       ├── 「N 天连胜」+ 火焰图标
│       └── 「LV.N」
├── Zone-A 左侧/主列（常用模版）
│   ├── 区块标题「我的常用」+ 链「查看全部」
│   └── 横向卡片列表
│       └── Card×N：图标、标题、描述、「N 积分/分钟」、圆形播放
└── Zone-B 右侧列
    ├── Widget-Focus（进行中任务）〔默认小窗，可点击铺满〕
    │   ├── 标题行：任务名 +「正在进行」+ 倍率标签
    │   ├── 大数字计时「已专注时长」
    │   ├── 「本次已获得 +X 积分」
    │   └── 按钮「暂停」「结算」
    └── Widget-Leaderboard「今日榜单」
        └── 排行行（名次、昵称、积分）
```

### 4.3 接口映射（逐项）

| 交互 | 接口 | 说明 |
|------|------|------|
| 首屏加载「我的常用」 | **〔缺口〕** OpenAPI 无「收藏/常用模版」；可用 `POST /api/reward/task-templates/query` 全量或按标签筛选后前端截取 | 或与后端增加 `favorites` |
| 点击播放 | `POST /api/reward/task-executions/start` | body：`taskTemplateId`、`clientTime`（秒） |
| 暂停 | `POST /api/reward/task-executions/pause` | `id`、`clientTime` |
| 结算（完成） | `POST /api/reward/task-executions/complete` | 响应 `reward`；后再 `POST /api/reward/user/points` |
| 恢复计时展示 / 断线重进 | `POST /api/reward/task-executions`（ongoing）+ `GET /api/reward/task-executions/by-no/{instanceNo}` | 与现网逻辑一致 |
| 「本次已获得 +X」实时刷新 | 优先 **前端按已跑时长 × 模版倍率估算**；最终以 **complete 响应** 为准 | 模版倍率 **〔缺口〕** 若仅 name/description 则需扩展模板模型 |
| 连胜、LV、今日榜单 | **〔缺口〕** 无对应 OpenAPI | 需 Reward 扩展或活动服务 |

### 4.4 专注模式（布局态）

- **触发**：点击 Widget-Focus 标题区/放大图标（设计稿具体控件以 Figma 为准）。
- **表现**：同一 `task execution` 状态；**仅 CSS/布局** 铺满 L2 或全屏；**不新增** REST 调用。
- **退出铺满**：缩回小窗；不取消执行，除非用户点暂停/结算。

| 按记录 id | `GET /api/reward/point-records/{id}` |
| 按订单号补强 | `GET /api/reward/purchase-record/by-no/{purchaseNo}`（若列表行带 `purchaseNo`） |

**交互**：「前往背包」→ 路由 **§8 背包**（可带 query 高亮某物品 **〔前端态〕**）。

## 8. 背包（侧栏 5）

### 8.2 接口

**〔缺口〕**：设计若需「物品使用」按钮，需 Reward 提供使用/消耗道具接口。

## 11. 缺口汇总（实现前评审）

| 设计能力 | 建议 |
|----------|------|
