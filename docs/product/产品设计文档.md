# 学习奖励应用 — 产品设计文档

## 1. 文档目的与范围

本文档基于 **star-sso**、**star-reward** 的 OpenAPI 能力、前端仓库已实现的页面与 API 封装，以及产品示意图（登录/仪表盘/任务/专注/积分商城/明细/个人设置等）中的**期望能力**，梳理**功能模块**、**当前产品形态**与**设计差距**，供迭代对齐。

范围：前端应用 `study-reward-app`；后端以 SSO 与 Reward 微服务为准。

## 2. 产品定位

- **一句话**：通过「任务模板 + 计时执行」将学习/工作行为量化，完成后获得积分，在商城兑换虚拟奖励，形成正向反馈闭环。
- **价值**：降低启动成本（模板）、可视化进度（进行中任务与计时）、即时激励（积分变动与兑换）。
- **技术拓扑**：应用依赖 **star-sso**（登录态与用户信息）与 **star-reward**（任务、商品、积分、兑换、背包）。

## 3. 核心用户旅程（目标态）

与示意图一致的理想主路径：

1. **注册/登录** → 获得 JWT，进入主界面。
2. **首页/仪表盘** → 展示总积分、快捷入口（我的任务、积分商城等）。
3. **任务** → 创建任务（名称、分类/图标、描述、期望积分等）→ 卡片列表浏览。
4. **专注模式** → 全屏或大卡片计时，与具体任务关联；结束可结算积分。
5. **积分商城** → 浏览商品 → 详情 → 兑换 → 成功反馈（扣分动效）。
6. **积分明细 / 兑换记录** → 表格或列表查看流水与状态。
7. **个人设置** → 头像、昵称、通知、**账号绑定**（第三方 SSO）。

当前实现的主路径见第 5 节；与示意图的差异见第 6 节。

## 4. 信息架构（模块划分）

| 模块 | 设计意图（示意图） | 后端归属 |
|------|-------------------|----------|
| 认证与账号 | 登录、注册、登出、用户信息、账号绑定、个人资料 | 主要为 star-sso；绑定能力依赖 SSO 产品演进 |
| 任务与项目 | 任务模板 CRUD、列表/网格、分类与积分展示 | star-reward（任务模板 + 任务执行） |
| 专注与计时 | 倒计时、开始/暂停/继续/完成/取消、与任务实例绑定 | star-reward（任务执行状态机 + clientTime） |
| 积分与激励 | 余额展示、完成任务发奖、流水展示 | star-reward（积分查询、积分记录、完成接口返回 reward） |
| 商城与资产 | 商品浏览、兑换、背包、购买记录详情 | star-reward（商品、兑换、背包、购买记录） |
| 壳层与偏好 | 侧栏/顶栏导航、主题、个性化样式 | 前端本地为主；可与后端扩展用户偏好 |

## 5. 当前产品形态（已实现）

- **布局**：单页应用，顶栏（标题、进行中任务入口、积分、用户菜单、主题）+ 底部 Tab：**学习任务**、**积分商城**、**我的背包**、**积分记录**。
- **认证**：独立登录页；`login` / `register` 成功后写 Token；主界面用 `user/info` 展示昵称/用户名；退出为**本地清除 Token**（未调用服务端登出接口）。
- **任务**：任务模板增删改查；从模板启动执行；执行支持开始/暂停/恢复/完成/取消，计时与 `clientTime` 与后端对齐；列表含筛选、分页、新建弹窗（名称+描述，与后端模板字段一致）。
- **商城**：商品列表、兑换、积分刷新；背包列表；积分记录分页与类型筛选。
- **个性化**：多主题、自定义样式（本地存储 + 弹窗编辑器）。

**与示意图相比**：当前**无**独立「仪表盘」页、**无**示意图中的**分类图标网格**、**无**全屏「专注模式」视觉壳（计时能力已在任务 Tab 内实现）、**无**个人设置/账号绑定页（用户菜单中「设置」为占位）。

## 6. 设计差距与建议优先级

| 期望（示意图） | 现状 | 建议 |
|----------------|------|------|
| 分栏登录页品牌区 + 表单 | 已有登录/注册流程，视觉可逐步贴近 | UI 还原 |
| 仪表盘总览与快捷入口 | Tab 即主页，无独立 Dashboard | 新增路由或首屏聚合组件 |
| 创建任务时的品类/图标 | 模板仅 name/description | 扩展模板模型或前端映射 + 后端字段 |
| 全屏专注模式 | TaskManager 内计时 | 可选全屏视图组件，仍调用同一套 TaskExecution API |
| 兑换成功/获得积分动效 | 基础 Toast/刷新 | 加强反馈组件 |
| 个人设置、账号绑定、通知 | 未实现 | 依赖 star-sso 是否提供绑定/资料/通知 API |
| 服务端登出 | 仅 clearToken | 可对接 `POST /api/sso/logout` |

## 7. 非功能与体验原则

- **鉴权**：业务请求带 `Authorization: Bearer <token>`；401 清理 Token 并回登录。
- **一致性**：积分数字在完成任务、兑换后及时刷新；计时时注意前后端时间与 `clientTime` 约定（见项目内任务计时相关规则）。
- **可访问性**：关键操作有明确按钮文案与禁用态；错误通过统一 API 错误提示呈现。

## 8. 文档维护

后端 OpenAPI 变更时，应同步更新《功能文档》中的接口映射表；示意图迭代时更新本章「设计差距」表。
